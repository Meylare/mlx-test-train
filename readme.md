## 📦 О структуре чекпоинтов (LoRA)

В процессе обучения в папке `checkpoints/epoch_N/` сохраняются только измененные части модели, а не вся нейросеть целиком.

### Почему файлы такие маленькие?
Мы используем метод **LoRA (Low-Rank Adaptation)**. Вместо того чтобы перезаписывать все 7 миллиардов параметров модели Qwen2.5-VL (что весило бы >15 ГБ), мы обучаем только дополнительные "адаптеры" — крошечные слои, которые накладываются поверх основной модели.

**В папке каждой эпохи вы найдете:**
1. `lora_adapter.npz` (~200 МБ) — обученные знания модели о виральности.
2. `viral_head.npz` (~5 МБ) — веса нашей финальной "головы", которая переводит выводы нейросети в числовой индекс.

### Как это использовать для предсказаний?
Сама база (огромный "замок" Qwen) остается неизменной в кэше вашего компьютера. Чтобы запустить готовую модель, скрипт инференса будет:
1. Загружать чистую модель `Qwen2.5-VL-7B-Instruct-4bit`.
2. Накладывать сверху ваш `lora_adapter.npz`.
3. Подключать `viral_head.npz`.

Это позволяет экономить десятки гигабайт места на диске и делиться обученной моделью, просто пересылая маленькие файлы.

## Inference by video_id (SQLite + GCS)

### 1) Prepare SQLite DB
Create a JSONL file with one object per line:
```json
{"video_id":"abc123","gcs_uri":"gs://my-bucket/path/video.mp4","transcript":"...","system_prompt":"...","metadata":{"title":"..."}}
```
Ingest it:
```bash
python scripts/ingest_metadata.py --input-jsonl data/videos.jsonl
```

### 2) Authenticate to GCS (ADC)
```bash
gcloud auth application-default login
```

### 3) Run inference
```bash
python scripts/run_inference.py --video-id abc123 --checkpoint-dir checkpoints/epoch_3
```

Optional JSON output:
```bash
python scripts/run_inference.py --video-id abc123 --out-json outputs/abc123.json
```

Notes:
- `gcs_uri` can also be a local file path for quick testing.
- Default cache dir: `.cache/videos` (disable with `--no-cache`).




🛠 Технические изменения и оптимизация пайплайна
В ходе настройки инференса были внесены критические изменения в src/inference/pipeline.py, чтобы адаптировать общую логику под специфику архитектуры Qwen2.5-VL и обеспечить корректную работу блока Timecode Advisor.

1. Исправление извлечения эмбеддингов (Spatial Pooling)
Архитектура Qwen2.5-VL использует механизм сжатия данных: визуальный энкодер объединяет каждые 4 соседних патча (2x2) в один токен.

Проблема: Скрипт не мог найти видео-токены в общей последовательности, так как ожидал их в 4 раза больше, чем было на самом деле.

Решение: В функции _extract_video_embeddings добавлен расчет num_video_tokens = (T * H * W) // 4. Это позволило корректно определять границы видео внутри текста и проводить градиентный анализ.

2. Синхронизация таймкодов (Temporal Alignment)
Модель объединяет каждые 2 кадра в 1 временной блок (Temporal Pooling). При этом Advisor изначально использовал нативный FPS видео для расчета времени, что приводило к «схлопыванию» всех советов в первые доли секунды.

Решение: Реализован расчет «эффективного FPS» для Advisor. Теперь таймкоды советов распределяются равномерно по всей длине видео (duration_sec), учитывая количество проанализированных моделью блоков.

Результат: Если видео длится 10 секунд, советы будут привязаны к реальным моментам (например, 0с, 5с, 10с), а не к 0.1с.

3. Стабильность кода
Исправлен NameError: name 'Optional' is not defined путем добавления соответствующего импорта в pipeline.py.

Оптимизирована функция _collect_video_token_ids для более надежного определения специальных токенов видео в различных версиях процессоров Qwen.

📈 Рекомендации по качеству анализа (Max Frames)
Параметр --max-frames определяет, сколько кадров будет извлечено из видео для анализа. Из-за особенностей модели (сжатие 2 в 1), это напрямую влияет на детализацию советов:

Входные кадры	Точки анализа (блоки)	Уровень детализации
6 кадров	3 блока	Базовый: Только "Начало, Середина, Конец".
10 кадров	5 блоков	Средний: Более дробное деление сегментов.
16-20 кадров	8-10 блоков	Высокий: Детальный анализ динамики внутри сцен.
32 кадра	16 блоков	Максимальный: Наилучшая точность для Timecode Advisor.
Рекомендуемое значение для финтьюна и инференса:
Для получения максимально глубоких советов по улучшению видео используйте --max-frames 32. Это позволит Advisor увидеть микро-нюансы монтажа и дать точные рекомендации по каждой секунде контента.

code
Bash
# Пример запуска с максимальной детализацией
PYTHONPATH=. python scripts/run_inference.py --video-id ID --max-frames 32 --advice
🔑 Работа с Google Cloud Storage (GCS)
Для корректной работы с приватными бакетами в режиме инференса рекомендуется использовать JSON-ключ сервисного аккаунта:

code
Bash
GOOGLE_APPLICATION_CREDENTIALS="path/to/your/key.json" PYTHONPATH=. python scripts/run_inference.py --video-id YOUR_ID --advice
Скрипт автоматически скачает видео, проанализирует его и сохранит в локальный кэш (.cache/videos) для ускорения повторных запусков.
